## 1. Executive Summary & Core Mission

### 1.1 The Clinical "Golden Hour"
In emergency medicine, the **Golden Hour** refers to the first 60 minutes following severe physical trauma or acute clinical onset (e.g., Anterior STEMI cardiac arrest, polytrauma, intracranial hemorrhage). Within this window:
- Preventing mortality hinges on reducing pre-hospital transit delays from an average of **38–54 minutes down to 8–12 minutes**.
- Emergency departments require predictive telemetry **before** the ambulance arrives so resuscitation bays, blood crossmatches, and surgical suites are pre-activated.

### 1.2 What is GoldenHour AI?
**GoldenHour AI** is a next-generation Clinical Emergency Operating System (OS) bridging the gap between bystanders, emergency dispatchers, in-transit paramedics, and receiving hospital trauma teams. 

Unlike legacy EMS systems that rely on slow verbal radio dispatch and fragmented paper records, GoldenHour AI features:
- **Instant One-Tap SOS with 3D Pain Mapping**: Citizens report traumatic symptoms directly on a luminous 3D Anatomical Trauma Twin.
- **Multilingual AI Voice Triage**: Speech-to-text supporting regional Indian languages (Telugu, Hindi, English) with automatic Emergency Severity Index (ESI Level 1–5) rule suggestion.
- **Biometric Trauma Twin Telemetry**: Real-time arterial pressure waveforms, SpO₂, Glasgow Coma Scale (GCS), and 3D jelly medication formulations streamed live from the ambulance to the hospital.
- **Palantir-Grade Ambulance Command Deck**: Dispatch map with real-time transit corridors, traffic beacon pills, vehicle fleet selection (Air Evacuation Helicopter vs Ground Mobile ICU), and active triage lists.
- **Zero-Gatekeeping Doctor Case Board**: Emergency physicians access 3D interactive clinical dossiers, allergy warnings, and 90-second automated trauma bay reservation holds without administrative delay.
- **Good Samaritan Volunteer AED Mesh**: Crowdsourced dispatch of verified first-responders equipped with automated external defibrillators within a 500-meter radius.

## 3. The Anti-Framelock & Asset Liberation Philosophy

A common trap in medical UI engineering is treating 3D visual assets like traditional flat web images—trapping them inside small avatar containers, tucking them behind collapsed accordion toggles, or covering them with heavy text overlays. 

The user's feedback established five core rules for asset placement:

```
[WRONG: The Framelock Trap]                  [RIGHT: The Mivo Asset Liberation]
+-------------------------------+             +-----------------------------------------+
| [v] Open 3D Scan (Dropdown)   |             |  Matthew Johnson 26yo                   |
+-------------------------------+             |                                         |
| [12x12] Metformin Lozenge     |             |      [PRISTINE 3D CRYSTAL TWIN]         |
| [12x12] Ibuprofen Capsule     |             |      (Zero dimming gradients)           |
|                               |             |                                         |
| Dark gradient covering 70%    |             |  +---------------+   +---------------+  |
| of torso with text labels     |             |  | Pressure Wave |   | Jelly Meds    |  |
+-------------------------------+             |  +---------------+   +---------------+  |
                                              |  Floating stadium pills flank the body  |
                                              +-----------------------------------------+
```

### The 5 Golden Rules of Asset Integration:
1. **Never Gate the Hero Behind a Toggle**: In an emergency or presentation setting, the 3D anatomical model is the emotional and functional anchor. It must be rendered full-size immediately on mount with zero click gates.
2. **Never Squish Volumetric Renders to Button Icons**: High-fidelity 3D assets lose their refractive beauty when reduced to `48x48px` or `w-12 h-12`. Render them at a minimum of `aspect-[16/9]` or `aspect-[16/7]` with generous negative space.
3. **Flank with Stadium Pills Instead of Overlapping Text**: Do not place paragraphs of text or dark vignette overlays directly over the crystalline anatomy. Position telemetry cards (Arterial Pressure, Medications, ESI Level) as floating stadium pills *beside* or *below* the 3D model.
4. **Preserve Subsurface Scattering & Rim Lighting**: Avoid heavy dark gradient masks (e.g., `bg-gradient-to-t from-slate-950/80`). Use crystal rim-lighting (`rgba(255, 255, 255, 0.4)`) and transparent-to-frosted transitions so the lighting remains crisp and luminous.
5. **Dynamic Symptom Reactivity**: When a user selects a symptom (e.g., `chest_pain`), the 3D model must dynamically light up the corresponding hotspot (e.g., cardiac zone), adjust the severity dial, and update telemetry in real time.

## 7. Technical Architecture & Regulatory Constraints

### 7.1 Zero-Aadhaar Storage Compliance (Section 29 Aadhaar Act 2016)
Under Indian statutory compliance (Section 29 of the Aadhaar Act, 2016), storing plaintext 12-digit Aadhaar numbers or biometric identities in pre-hospital software is strictly illegal. 

GoldenHour AI implements a **One-Way Cryptographic HMAC-SHA256 Tokenizer**:
```typescript
// services/crypto.ts
export function generateEphemeralPatientToken(aadhaarLast4: string, timestamp: number): string {
  const salt = import.meta.env.VITE_HMAC_SECRET || 'goldenhour-clinical-ephemeral';
  // Generates irreversible privacy-preserving clinical handle
  return 'GH-' + hmacSha256(`${aadhaarLast4}:${timestamp}`, salt).slice(0, 8).toUpperCase();
}
```
* **Rule**: Neither the database, localStorage, nor API logs ever record plaintext Aadhaar identifiers.

### 7.2 Clinical Decision Support Non-Diagnostic Notice
Per regulatory guidelines for AI medical software (SaMD - Software as a Medical Device), all algorithmic triage suggestions must feature an immutable simulation notice:
```tsx
// components/ui/status-badges.tsx
export const DecisionSupportBanner: React.FC = () => (
  <div className="p-2.5 rounded-2xl bg-amber-500/10 border border-amber-500/30 text-[11px] text-amber-700 dark:text-amber-300 font-medium flex items-center gap-2">
    <ShieldAlert className="w-4 h-4 text-amber-500 shrink-0" />
    <span>Decision Support Only — Does not replace physician clinical judgment. Protocol: Apollo Regional Polytrauma.</span>
  </div>
);
```

### 7.3 Offline-First Resilience & SMS Fallback
In scenarios where 4G/5G connectivity drops during rural transit:
1. Patient vitals and GPS coordinates are packed into an ultra-compact **Base64 binary payload (max 140 bytes)**.
2. The payload is automatically dispatched via Android Telephony Manager SMS fallback to the emergency dispatch hub.
3. Upon reconnection, the client automatically reconciles state with the central server.

### 7.4 90-Second Emergency Bay Reservation Hold
To eliminate phantom ambulance arrivals:
- When a doctor locks a resuscitation bay ([`S14DoctorCaseBoard.tsx`](file:///c:/GoldenHour/src/screens/S14DoctorCaseBoard.tsx)), a live **90-second automated reservation hold** countdown is initiated.
- If the incoming ambulance fails to update its beacon or confirm arrival within the countdown window, the hold automatically expires and alerts the charge nurse to release the bay.
